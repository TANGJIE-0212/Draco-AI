# V3 四周课程大纲与拟出题蓝图（审查稿）

|---|---|---|
| 第一周 | AI 原理：从 Token 到生成 | 完整解释大模型从输入文字到生成输出的过程，并能分析幻觉原因 |

## 共同设计原则与通俗化包装规范

- **受众定位**：面向 14 岁、数理逻辑较好的初中生。保持底层技术逻辑真实准确，不讲虚假伪科学，但**绝不堆砌生硬数学符号和晦涩学术术语**。
- **比喻垫台阶，机制讲透彻**：每一个抽象硬核概念，必须先用一个**贴近青少年日常的精准直觉比喻（如查字典、雷达扫描、调音台、点外卖、班级发通知等）**垫平认知台阶，再落地到真实因果机制。
- **5 个关键认知台阶的通俗化统一口径**：
  1. **静态 Embedding → QKV Attention**：用“一词多义”破题。“苹果”在字典里只有一个固定坐标（静态 Embedding），但“红富士苹果”和“苹果发布会”里的苹果含义不同。**QKV 就像是每个词拿着放大镜去询问周围的词（Q 提问、K 匹配、V 提炼）**，把上下文信息混合进来，完成动态理解。
  2. **多模态两套发动机（看图 vs 画图）**：明确分清**“看图（视觉编码器）”**是把整张图片切成拼图（Patch）、提取特征压成向量送进大脑；而**“画图（扩散模型）”**完全相反，是从满屏幕白花花的电视雪花噪声中，根据提示词一步一步把多余杂点擦除、雕刻出去，还原出清晰画面。
  3. **思维链（CoT）与内置推理模型**：区分“外置提示”与“内置推理”。普通对话模型需要你写 Prompt 提醒它“请分三步一步步写草稿”；而新一代原生推理模型（如 DeepSeek-R1 / o1）是在出厂前就训练成了“先在草稿纸上憋一大段推理，再交卷”的学霸习惯。
  4. **后端工程概念生活化（如幂等性）**：用“班长发群通知”或“点外卖扣款”包装。向全班发通知时网络卡了一下，系统自动重试 3 次；如果系统具备**防重复机制（幂等性）**，大家只会收到 1 条，否则会瞬间被 3 条一模一样的消息轰炸。
  5. **第三周做短片 → 第四周做 Agent 的自然承接**：在第三周，查资料、写咒语、点生成、拼剪辑全是学生自己——学生是“人肉总指挥”。第四周的核心就是：**怎样把这个写计划、挑工具、盯着结果跑的‘总指挥’角色，交由 AI 自己去自主完成？** 这就是 Agent。
- **题目设计偏向**：重点考查“为什么会这样”、“出了错是哪一步导致的”、“参数怎么调”、“实验怎么比”，坚决避免死记硬背概念定义。
- 每天正式题库拟设 15 道；本稿列出的 5 道代表题用于展示题型和深度，**不是把每道题换三个说法扩成 15 题**。
- **正式扩题规则**：先把当天大纲拆成知识点覆盖矩阵，再为不同知识点命题。原则上，同一狭窄考点不超过 2 题；确需重复时，必须分别考查“识别、解释、应用或诊断”等不同能力，不能正问一次、反问一次、换句话再问一次。
- **15 题建议结构**：约 5 题基础事实与概念、5 题关系理解与因果解释、3 题情境诊断与参数判断、2 题实验或综合应用。历史课可适当增加时间线和里程碑题，多模态课则增加诊断与实验题。
- 第三周正式题库按约 40% 原理、30% 缺陷诊断、30% 动手实验配置。
- 不要求学生展示隐藏思维链，只要求可验证的中间结果、证据和检查过程。

## 审查重点

1. 每天的知识边界是否合适，有没有过浅或跨得太快？
2. 四周之间是否形成“模型原理 → 指令工程 → 多模态 → Agent 系统”的递进？
3. 代表题是否真正检验理解，而不是换一种方式背术语？
4. 第三周是否兼顾原理与兴趣实践，而没有退化成工具说明书？
5. 第四周是否讲清 Agent Engineering，而不只是介绍某个 Agent 产品？

# 第一周：AI 原理——从 Token 到生成

## 第 1 天｜AI 发展史：技术为什么一代代变化

**学习目标**：理解符号主义、专家系统、机器学习、深度学习、Transformer 和生成式 AI 的演进关系。

**核心大纲**
- 图灵测试和达特茅斯会议：AI 问题如何被提出。
- 专家系统：把人的知识写成规则，优势与瓶颈是什么。
- 机器学习：从数据中寻找模式，与手写规则的区别。
- 深度学习：自动学习特征，为什么依赖数据和算力。
- Transformer 与生成式 AI：从识别、预测走向通用内容生成。

**课堂演示**：对比一个 if-else 规则分类器和一个从样例学习的分类器，讨论遇到新表达时谁更容易失效。

**达标标准**：能按时间线解释技术路线；能说明每次转变解决了什么旧问题，也带来了什么新限制。

**代表性拟题**
1. [历史推理] 为什么 1956 年达特茅斯会议重要，而不能只把它看成一次普通学术会议？
2. [比较] 专家系统与机器学习系统获得“判断规则”的方式有什么根本区别？
3. [诊断] 一个系统只能处理工程师提前写过的情况，它更接近哪条技术路线？依据是什么？
4. [因果] 为什么数据、GPU 和算法进步需要同时出现，深度学习才会快速发展？
5. [综合] 用一条因果链解释从专家系统到生成式 AI 的技术演进。

## 第 2 天｜Token 与 Tokenizer：模型怎样切开文字

**学习目标**：理解字符、词与 Token 的区别，掌握 BPE 直觉，以及 Token 数量与上下文、成本的关系。

**核心大纲**
- Token 是模型处理的离散编号，不一定等于一个字或一个词。
- 中文、英文、数字、标点和代码的切分差异。
- 词表与未知词问题。
- BPE：从字符开始，反复合并高频片段。
- Token 数量如何影响上下文占用、速度与调用成本。

**课堂实验**：使用同一 tokenizer 比较中文句子、英文句子、日期、罕见姓名和代码的切分结果。

**达标标准**：能解释不同文本为何 Token 数不同；能手工演示一轮简化 BPE 合并。

**代表性拟题**
1. [概念辨析] 为什么“一个汉字就是一个 Token”不是普遍正确的说法？
2. [BPE 操作] 给出字符序列和频次表，请完成前两轮高频片段合并。
3. [诊断] 同样长度的自然语言和代码，为什么可能消耗不同数量的 Token？
4. [工程判断] 上下文窗口还剩 800 Token，但资料约有 1500 Token，应如何处理并说明理由？
5. [实验设计] 怎样公平比较两个 tokenizer 对中英文混合文本的处理效率？

## 第 3 天｜Embedding：Token 怎样进入语义空间

**学习目标**：理解 Token ID 与含义不同；理解向量、维度、距离和余弦相似度的直觉。

**核心大纲**
- Token ID 只是编号，Embedding 才是可计算的向量表示。
- 向量维度与特征表达能力。
- 相似语义为何可能在向量空间中靠近。
- 欧氏距离与余弦相似度分别关注什么。
- 同一个词在不同上下文中为何需要不同表示。

**课堂实验**：在二维坐标中放置“猫、狗、汽车、自行车”等概念，并讨论坐标轴假设与相似度局限。

**达标标准**：能计算简单二维向量的余弦相似度；能说明语义接近不等于事实相同。

**代表性拟题**
1. [解释] 为什么 Token ID 100 和 101 相邻，不代表两个 Token 的含义相近？
2. [计算直觉] 两个向量方向几乎相同但长度差异很大，余弦相似度会呈现什么特点？
3. [比较] 余弦相似度和欧氏距离分别更关注向量的什么性质？
4. [语境诊断] “苹果很好吃”和“苹果发布新手机”中的“苹果”为什么不能使用完全相同的语义表示？
5. [边界] Embedding 检索到语义相近的文档，为什么仍不能证明文档中的结论正确？

## 第 4 天｜Transformer 与 Attention：模型怎样利用上下文（词语的雷达扫描）

**学习目标**：理解从静态 Embedding 到动态上下文的跨越，用通俗直觉理解 Attention（Q/K/V）机制与多头注意力。

**通俗化核心包装**
- **为什么需要 Attention**：“苹果”在字典里只有一个固定的数字坐标（静态 Embedding），那模型怎么区分“好吃的苹果”和“苹果公司发布新手机”？
- **词语的雷达扫描**：每个词都像带着雷达天线，在句子中扫视其他词，把和自己最相关的词语含义吸纳进来。
- **Q / K / V 的学生会比喻**：
  - **Query（查询/找什么）**：当前词举着牌子提问（例如“谁是‘它’指代的主人？”）。
  - **Key（特征/匹配牌）**：句子里每个候选词挂着的身份牌（例如“箱子：大”、“奖杯：沉”）。
  - **Value（实质内容/装进背包）**：一旦 Q 和 K 算出了很高的匹配分，就把对应词的真实语义信息打包提取出来。
- **注意力权重与 Softmax**：把雷达扫描到的强弱信号归一化为百分比（权重总和为 100%）。
- **位置编码（Positional Encoding）**：就像全班排队报数编号。如果不给每个词标上座位号，模型看“猫追狗”和“狗追猫”就是一模一样的一堆词。

**课堂演示**：用“奖杯放不进箱子，因为它太大了”分析“它”的指代，学生扮演 Q、K、V 角色分配注意力百分比。

**达标标准**：能用 Q/K/V 直觉解释一次上下文匹配；能说明高 Attention 权重不代表事实一定正确。

**代表性拟题**
1. [连线] 在“图书借阅处找资料”比喻中，读者想找的主题（Q）、图书封面标签（K）、书里的具体知识（V）分别对应什么？
2. [计算直觉] 三个候选词的雷达匹配分不同，经过 Softmax 计算后，分配到每个词的注意力百分比总和一定是多少？
3. [诊断] 模型把句子里的代词“它”指向了错误的对象，可能是在雷达扫描（Attention）计算时哪两个词的特征匹配出了偏差？
4. [反事实] 如果模型在输入时把全班报数编号（位置编码）丢掉了，它为什么完全无法分清“张三借给李四五块钱”和“李四借给张三五块钱”？
5. [边界] 为什么某个词获得了 95% 的极高注意力权重，我们依然不能断定模型说出的结论 100% 符合客观事实？

## 第 5 天｜从 Logits 到采样：Temperature 怎样改变输出

**学习目标**：串起 Logits、Softmax、Temperature、Top-k、Top-p、Greedy 与 Sampling。

**核心大纲**
- Logits 是候选 Token 的原始分数。
- Softmax 将分数转换为总和为 1 的概率分布。
- Temperature 改变分布尖锐程度，而不创造新知识。
- Top-k 固定候选数量，Top-p 根据累计概率动态截断。
- Greedy 与随机采样的稳定性、多样性取舍。

**课堂实验**：给定四个候选 Token 的分数，比较低温、常温和高温下概率分布的相对变化，再进行多次抽样。

**达标标准**：能解释完整采样链；能为代码生成、事实问答和创意写作选择参数并说明原因。

**代表性拟题**
1. [流程排序] 将 Logits、Temperature 缩放、Softmax、候选截断和 Sampling 按生成顺序排列。
2. [概率直觉] Temperature 降低后，最高概率 Token 与其他候选的差距通常怎样变化？
3. [比较] Top-k 与 Top-p 控制候选池的方式有何不同？
4. [场景判断] 写 SQL 和写奇幻故事分别更适合怎样的采样策略？为什么？
5. [纠错] “Temperature 越低，答案事实准确率一定越高。”这句话错在哪里？

## 第 6 天｜训练、推理与幻觉：模型为什么会自信地说错

**学习目标**：区分预训练、微调、对齐和推理；理解幻觉机制以及 RAG、计算器和检索工具的作用。

**核心大纲**
- 预训练学习语言与世界模式，不等于建立可查询的事实数据库。
- 微调与指令微调改变任务表现。
- 对齐改善行为边界，不保证知识永远正确。
- 推理阶段是在当前上下文中逐 Token 生成。
- 幻觉的来源：证据不足、上下文冲突、错误前提和生成目标。
- RAG 与工具把外部证据接入推理过程，但结果仍需核验。

**课堂实验**：让模型分别直接回答、读取可靠资料后回答、调用计算器后回答，对比三种答案及证据链。

**达标标准**：能诊断“缺知识、缺上下文、算错、幻觉、资料错误”；能选择合适的核验方式。

**代表性拟题**
1. [比较] 预训练、微调、对齐和推理分别发生在什么阶段，解决什么问题？
2. [诊断] 模型给出格式完美但不存在的论文引用，属于什么问题？为什么会发生？
3. [工具选择] 面对最新新闻、复杂算术和校内规章，分别应接入什么证据或工具？
4. [边界] RAG 为什么能降低部分幻觉，却不能保证答案百分之百正确？
5. [实验设计] 如何比较“直接回答”和“检索后回答”的事实准确率，而不只凭主观感觉？

## 第 7 天｜原理 Boss：完整解释一次模型生成

**学习目标**：串起 Text → Token → Embedding → Attention → Logits → Softmax → Sampling → Output，并定位不同失效点。

**核心大纲**
- 输入与 Tokenization。
- Embedding 与上下文表示。
- Transformer 层和 Attention。
- 输出 Logits 与概率分布。
- 采样策略与逐 Token 循环。
- 证据、工具和幻觉检查点。

**Boss 实验**：对一个短 Prompt 和一段模型输出画完整流程图，解释每一层输入输出，并为错误答案定位最可能的原因与验证方法。

**达标标准**：能够不用“AI 就是猜字”一句话带过，而是清楚解释完整链路及各模块的边界。

**代表性拟题**
1. [流程排序] 完整排列模型从文字输入到生成下一个 Token 的主要步骤。
2. [模块诊断] 模型误解多义词与模型选择了低概率词，分别更可能发生在哪些环节？
3. [综合解释] 为什么模型既能生成高质量文章，又可能编造不存在的事实？
4. [参数实验] 设计实验分别观察上下文、Temperature 和 Top-p 对结果的影响，每次只改变一个变量。
5. [Boss 开放题] 画出完整生成链路，在至少三个位置标注可能错误及对应核验手段。

# 第二周：Prompt Engineering——从指令到可评测系统

## 第 1 天｜目标、任务边界与成功标准

**学习目标**：把模糊愿望改成可执行、可验收的任务定义。

**核心大纲**：目标、受众、输入、输出、范围、成功标准、失败标准；“更好”为什么不可评测。

**课堂实验**：把“帮我写好一篇介绍”逐步改成可用测试验证的任务说明。

**达标标准**：能写出至少四项可观察标准，并识别互相冲突的要求。

**代表性拟题**
1. [诊断] “帮我写得专业一点”缺少哪些可执行信息？

## 第 4 天｜Zero-shot、One-shot 与 Few-shot

## 第 5 天｜任务拆解、规划与可验证中间结果（草稿纸原则）

**学习目标**：把复杂任务拆成可检查的步骤；理清普通对话模型的“外置步骤规划”与新一代深度推理模型（如 DeepSeek-R1、o1）的“内置草稿纸思考”的区别。

**通俗化核心包装**
- **AI 为什么需要打草稿**：让人一步心算出 $378 \times 492$ 几乎必错，但如果允许在草稿纸上分步列竖式，正确率就极高。大模型也是一个 Token 一个 Token 吐字，如果让它直接一口气给最终答案，它没有机会修正中间逻辑。
- **两种不同的“思考模式”**：
  - **外置规划（普通模型）**：需要你在 Prompt 里明确命令它：“第一步先提取数据，第二步计算，第三步核对，最后输出结果”。
  - **内置思考（推理学霸模型）**：训练时内部就养成了习惯，收到题目先自动在隐藏的 `<think>` 区域洋洋洒洒写草稿推理，最后再展示结论。
- **可验证的中间产物**：中间步骤不能光说空话，必须生成能供人类一眼核对的表格、清单或事实对照表。

**课堂实验**：将“根据三篇资料写比较报告”拆成“提取事实表 → 找矛盾点 → 拟定大纲 → 撰写正文”，对比直接输出与拆步输出的准确度。

**达标标准**：每一步都有输入、输出和通过条件；能分清什么是外置任务规划，什么是内置推理。

**代表性拟题**
1. [拆解] 如果要让 AI 策划一次初中生科技节活动，请将其拆成四个必须先出中间结果的可验证子步骤。
2. [概念辨析] 为什么现在的 DeepSeek-R1 或 OpenAI o1 会先弹出一个“深度思考中”的折叠框，它在里面其实在做什么？
3. [诊断] 你让普通大模型直接写一篇辩论赛攻防立论，发现它漏洞百出。如果你采用“草稿纸原则”，第一步最应该让它先输出什么？
4. [中间结果设计] 哪些中间产物（如提取清单、比对表格）能让人类一眼看出 AI 到底有没有在认真找证据？
5. [边界] 为什么在工程开发中，要求 AI 输出“清晰的中间证据表格”比让它输出一堆凌乱的内心独白更可靠？

## 第 6 天｜约束、Rubric、测试集与迭代调试

**学习目标**：用评测驱动 Prompt 迭代，并理解 Prompt Injection 的基本防护。

**核心大纲**：硬约束与软偏好；Rubric；正常、边界、对抗测试；V1→V2→V3 单变量实验；Injection 与数据隔离。

**代表性拟题**

# 第三周：多模态原理与实践（两套发动机：从看懂世界到创造画面）

## 第 1 天｜模型怎样“看图”：像素、Patch 与视觉 Token（把图片剪成拼图）

**学习目标**：理解图像输入给大模型的真实链路（视觉编码器），明白“看图”与“画图”是两套完全不同的底层发动机。

**通俗化核心包装**
- **两套发动机分水岭**：
  - **前两天学【看图】**：这是“分析大脑”。把一张高清图片切成小碎片（Patch），通过视觉编码器提取出特征，翻译成文字模型能看懂的“视觉 Token”。
  - **后五天学【画图/视频】**：这是“生成画师”。它的底层是完全不同的“扩散去噪（Diffusion）”技术。
- **图片拼图化（Patch）**：大模型没有肉眼，它把一张 $224 \times 224$ 的图片像切九宫格一样切成许多 $16 \times 16$ 的小方块（Patch），每个小方块变成一个向量。
- **视觉 Token vs 文本 Token**：文本 Token 是字典里的词或字，视觉 Token 是某个小方块里颜色、边缘、纹理的高度抽象。

**课堂实验**：逐步降低图片分辨率并裁切不同小块，观察模型对画面细节的描述如何衰减。

**达标标准**：能画出 像素 → 拼图切块(Patch) → 视觉Token → 编码器 → 语言大脑 的流程链路。

**代表性拟题**
1. [流程] 现实生活中的一张照片，是怎样被切成小方块（Patch）并变成模型能理解的视觉 Token 的？
2. [计算直觉] 如果把一张图片切成更细小的方块（比如从 16x16 缩小到 8x8），视觉 Token 的数量会变多还是变少？对计算量有什么影响？
3. [诊断] 模型能看懂整张图片里有一只猫，却看不清猫脖子项圈上的小字，这是在拼图切块（Patch）或分辨率的哪个环节丢失了信息？
4. [辨析] “看图大模型用的视觉 Token”和“写文章大模型用的文本 Token”本质上有什么区别与联系？
5. [实验] 怎样设计一个简单的测试，证明模型是真的“看懂了图片细节”，还是仅仅根据你提问里的提示词在瞎猜？

## 第 2 天｜图片理解与视觉幻觉（它真的看见了吗？）

**学习目标**：区分文字识别（OCR）、物体识别、空间关系判断，理解模型为什么会产生“看图脑补”的视觉幻觉。

**核心大纲**：
- **看得见的层级**：从底层的文字认读（OCR）、中层的物体识别，到高层的空间位置与图表逻辑。
- **视觉幻觉的成因**：当图片局部模糊、有阴影、被遮挡或者像素丢失时，模型会根据常识习惯自动“脑补”，生成看似合理但图里根本没有的假象。
- **客观观察 vs 主观推断**：“地上有一滩水（观察）”不等于“刚才有人打翻了水杯（推断）”。

**课堂实验**：对一张含小字、遮挡和图表的图片分层提问，并核对原图证据。

**达标标准**：每个结论都能标注“可见事实、合理推断或无法确认”。

**代表性拟题**
1. [分类] “图中招牌上有三个红色的字”与“这是一家生意火爆的百年老店”，分别属于客观视觉观察还是主观推断？
2. [诊断] 模型看一张柱状图时，读对了柱子的高低长短，却把 Y 轴的单位（万元读成元）弄错了，这属于哪种视觉理解缺陷？
3. [证据] 为什么仅仅给模型一张两个人在路边站着的清晰抓拍照片，我们绝不能让它推断两人的真实关系或住址？
4. [修正] 怎样改写一个“看图提问 Prompt”，能够有效防止多模态大模型在看不清的地方胡编乱造？
5. [实验] 如果给一张图片故意加一点点磨砂模糊或倒转方向，模型的回答发生了剧烈变化，说明了多模态识别的什么脆弱性？

## 第 3 天｜图像生成原理：扩散、潜空间与 Seed（在暴风雪中雕刻画面）

**学习目标**：理解生成式 AI 的另一套发动机（扩散模型 Diffusion），建立从纯随机噪声中反向去噪雕刻画面的直觉。

**通俗化核心包装**
- **雕像与暴风雪比喻**：
  - **正向加噪**：把一张高清名画不断撒上盐和雪花，直到最后变成屏幕上一片纯粹混乱的“电视雪花噪点”。
  - **反向去噪（AI在做的事）**：AI 像一位技艺高超的雕刻家，面对一片混乱的雪花点，按照你的提示词，一步一步把多余的噪点擦掉，最终“雕刻”出一幅绝美的画卷。
- **Seed（随机种子/宇宙起点）**：那片初始雪花点的独特排布编号。种子固定，起点的雪花就固定。
- **CFG（提示词遵从度旋钮）**：相当于指挥老师的音量。调太低，AI 放飞自我乱画；调太高，画面容易用力过猛、色彩失真或过曝变形。
- **Steps（雕刻步数）**：打磨画面的循环次数。太少画面糙，太多耗时间且边际收益递减。

**课堂演示**：固定 Prompt 分别改变 Seed、Steps 和 CFG，每次只变一个参数。

**达标标准**：能解释为什么完全相同的 Prompt 会生成不同的画；能熟练进行单变量参数调优。

**代表性拟题**
1. [原理] 用“擦除电视机雪花噪点”的比喻，解释扩散模型（Diffusion）是怎样从一片混乱中生成出高清画面的？
2. [参数直觉] 为什么在很多绘图软件里，只要你把“Seed（随机种子）”锁定为一个固定数字，生成的角色和构图就会基本保持稳定？
3. [诊断] 如果生成的画面出现了严重的色彩过饱和、人物边缘烧焦变黑或扭曲，最可能是哪个参数（如 CFG）调得太极端了？
4. [成本判断] 为什么生成图片时把去噪步数（Steps）从 30 步提高到 100 步，画面质量通常不会翻倍提升，反而白白浪费显卡算力？
5. [实验] 如果你想弄明白画面里的一只蝴蝶是提示词带来的还是随机噪点碰巧生成的，应该怎样设计对比实验？

## 第 5 天｜图转视频：时间一致性与镜头运动

**学习目标**：理解视频增加了时间维度，掌握关键帧、主体动作、镜头运动和连续性。

**代表性拟题**

## 第 7 天｜多模态 Boss：完成知识故事短片

**学习目标**：整合图像编码、扩散生成、时间一致性、TTS 与剪辑，完成 15–30 秒成片并解释技术选择。

**Boss 实验**：提交脚本与来源、主视觉、连续镜头、配音字幕、成片和发布检查记录。

**达标标准**：成片可播放、事实可回查、声画同步、素材合规；能诊断至少一个生成缺陷并说明修复过程。

**代表性拟题**
1. [流程] 从知识点到成片，需要依次完成哪些可验证产物？
2. [诊断] 画面漂亮但核心事实错误，为什么仍是不合格作品？
3. [原理解释] 成片中的哪项控制主要依赖 Seed，哪项主要依赖时间一致性约束？
4. [用户测试] 怎样验证观众真的理解了知识点，而不只是觉得视频好看？
5. [Boss 开放题] 提交 15–30 秒成片及技术说明、缺陷修复记录和发布检查表。

# 第四周：Agent Engineering——从 Chat 到受控执行系统（把总指挥权交给 AI）

## 第 1 天｜Chat、Workflow 与 Agent（从人肉调度到自主跑腿）

**学习目标**：区分单轮对话（Chat）、固定流水线（Workflow）与自主智能体（Agent），明确理解什么场景必须用 Agent，什么时候用 Agent 反而是画蛇添足。

**通俗化核心包装**
- **第三周到第四周的自然过渡**：
  - 在第三周做短视频时：找资料是你、写 Prompt 是你、点生成是你、剪辑拼图还是你——你就是那个**“人肉总调度员”**。
  - 第四周我们要学的是：**怎么把这个写计划、挑工具、盯着结果跑的‘总调度’角色，封装交给 AI 自己去自主完成？**
- **三种工作模式的生活化对比**：
  - **Chat（单轮问答 / 接线员）**：你问一句，它答一句。没有记忆，没有手脚，不能自己去打开网页查真实数据。
  - **Workflow（固定流水线 / 传送带）**：步骤绝对固定（第一步翻译，第二步排版，第三步存盘）。不管遇到什么情况都按死规矩硬跑。
  - **Agent（自主智能体 / 实习生）**：你给它一个宏观目标（“帮我调研三家节水设备”），它自己拆解步骤、自己决定先用搜索引擎还是先读文档、发现网页打不开能自己换个关键词，直到完成任务。

**课堂实验**：用“查明天下雨情况并向全班发送带伞提醒”对比 Chat、Workflow 和 Agent 三种实现方案的优缺点。

**达标标准**：能根据任务的不确定性、所需工具、状态记录和风险等级选择最合适的系统架构。

**代表性拟题**
1. [比较] 用“接线员”、“工厂传送带”和“带任务出门的实习生”分别对应 Chat、Workflow 和 Agent，说明它们在控制权和应变能力上的本质差异。
2. [选型] 批量把 100 个 Markdown 文件的标题自动提取并改名，为什么用固定的 Workflow 远比用自由的 Agent 更稳定、更省钱？
3. [诊断] 某个软件宣传自己是“超级 Agent”，但它仅仅是把你的问题送给大模型生成了一段漂亮话，完全没有调用任何工具和检查状态，它为什么只是个普通 Chatbot？
4. [风险] 为什么在银行转账、修改核心数据库等高风险、规则绝对明确的场景中，绝不应该直接放权给开放式 Agent 自主胡乱尝试？
5. [实验] 设计一个对比方案，比较面对同样一个复杂的调研任务时，人工一步步指挥与 Agent 自主循环执行在耗时、Token 成本与结果可控性上的差异。

## 第 2 天｜Goal、Plan、Task、State 与 Done

**学习目标**：把抽象目标拆成可执行任务，并用状态与完成条件控制推进。

**核心大纲**：Goal；Plan；Task 输入输出；State；依赖；Done Definition；动态重规划。

**课堂实验**：把“调研三种校园节水方案”建模成任务图和状态表。

**达标标准**：每个 Task 有输入、输出、状态和完成判定；能发现循环或遗漏依赖。

**代表性拟题**
1. [辨析] Goal 与 Done Definition 有什么区别？
2. [拆解] 将调研任务拆成带依赖关系的五个 Task。
3. [状态诊断] Agent 重复搜索同一关键词，State 可能漏记了什么？
4. [重规划] 某个关键来源不可访问时，Plan 应如何调整？
5. [流程设计] 为任务表定义 pending、running、blocked、done、failed 的转换条件。

## 第 3 天｜Function Calling 与工具工程

**学习目标**：理解模型不是直接执行工具，而是根据 Schema 提出结构化调用请求。

**核心大纲**：Tool Schema；参数类型和必填项；模型选择工具；执行器；结构化返回；超时、空结果、权限错误；读写风险。

**课堂演示**：查看天气工具的 JSON Schema，模拟一次正确调用和三种错误调用。

**达标标准**：能设计简单 Tool Schema；能区分模型错误、参数错误和工具错误。

**代表性拟题**
1. [流程] 从用户要求到工具结果进入上下文，中间有哪些参与者？
2. [Schema 修复] 一个搜索工具没有限制 query 长度和结果数量，可能产生什么问题？
3. [诊断] 参数合法但服务返回 403，应归类为什么错误？
4. [权限] 为什么“读取文件”和“删除文件”不应授予相同确认规则？
5. [错误处理] 超时、空结果和参数无效分别应重试、改参还是停止？

## 第 4 天｜Agent Loop：Plan–Act–Observe–Update

**学习目标**：理解循环执行、上下文管理、状态更新和最大步数。

**核心大纲**：计划；行动；观察；更新；局部重规划；上下文压缩；重复检测；步数与资源预算。

**课堂实验**：阅读一段 Agent 运行日志，标出每轮的 Plan、Act、Observe 和 State Update。

**达标标准**：能定位循环不前进的原因；能定义最大步数和进展判定。

**代表性拟题**
1. [排序] 将 Plan、Act、Observe、Update 排成一轮完整循环。
2. [日志诊断] Agent 连续三次调用相同工具且参数相同，下一步应怎样处理？
3. [上下文] 为什么不能把无限增长的全部运行历史原样塞回模型？
4. [状态] Observe 与 Update 有何区别？
5. [停止条件] 达到最大步数但目标未完成时，Agent 应返回哪些信息？

## 第 5 天｜Memory、RAG 与权限边界

**学习目标**：区分当前上下文、短期状态、长期记忆和外部知识库，设计写入、过期与删除规则。

**核心大纲**：Working Memory；Long-term Memory；RAG；来源与时间戳；写入条件；过期删除；最小权限与敏感数据。

**课堂实验**：为学习 Agent 分类十条信息：仅本轮使用、可长期保存、需确认后保存、禁止保存。

**达标标准**：能说明每条记忆为什么保存、保存多久、谁可读取、如何删除。

**代表性拟题**
1. [比较] 长期记忆与 RAG 知识库的用途有什么不同？
2. [写入判断] 用户一次性的情绪表达是否应永久写入记忆？为什么？
3. [诊断] Agent 总引用去年的课程表，应补充什么记忆治理机制？
4. [权限] 最小权限原则怎样应用在记忆读取与工具调用上？
5. [设计] 为“用户偏好”定义来源、确认、时间戳、过期和删除字段。

## 第 6 天｜评测、检查点与失败恢复（给实习生系上安全绳）

**学习目标**：理解 Agent 在现实运行中必然会遇到断网、报错和逻辑走偏；掌握关键检查点（Human-in-the-loop）、防重复执行（幂等性）与自动回退停止机制。

**通俗化核心包装**
- **防重复机制（幂等性）的生活化直觉**：
  - 班长用 Agent 给全班发紧急通知，中途网络信号卡顿了 2 秒，系统误以为发送失败，自动连续重试了 3 次。
  - 如果通知接口具备**“防重复（幂等性）”**设计，大家只会收到 1 条通知；如果不具备，大家手机会被 3 条一模一样的信息轰炸。
- **关键检查点（Human-in-the-loop / 人在回路）**：
  - 像学开车时的副驾驶刹车板。只读搜索、整理数据可以让 Agent 自由狂奔；但遇到“删除文件、群发消息、对外付款”等高风险动作，必须弹出提示框“请人类主人点击确认”才能放行。
- **重试 vs 回退 vs 停止**：
  - 瞬时网络卡顿 $\rightarrow$ 等 1 秒自动**重试**。
  - 搜索了 5 次全无结果 $\rightarrow$ 自动**回退**到上一步更换搜索策略。
  - 发现越权或达到最大步数 $\rightarrow$ 立即**安全停止**并向人类报错。

**课堂实验**：向调研 Agent 故意注入网页 404、API 超时、权限被拒等故障，观察它是在死循环还是在安全求助。

**达标标准**：能为不同类型的故障设计合理的重试、回退、人工确认和停止规则。

**代表性拟题**
1. [策略选择] 当 Agent 遇到“校园内网临时超时”与“密码权限被拒绝”时，为什么前者可以自动重试，而后者必须立刻停止并找人类？
2. [生活化幂等] 用“班长发群通知重试 3 次却只产生 1 条消息”的例子，解释为什么涉及写入和发送的工具必须具备“幂等性（防重复）”？
3. [检查点设计] 在一个“帮老师整理作业并给家长发短信反馈”的 Agent 流程中，哪一个步骤必须设置强制的人工确认检查点（Human-in-the-loop）？
4. [评测标准] 如果一个 Agent 最终交上来的调研报告完美无缺，但在执行中途私自翻看了未经授权的个人隐私文件夹，这个任务在工程评测上应该判定通过还是严重违规失败？
5. [恢复设计] 如果 Agent 在对比两个公开数据源时发现双方数字互相矛盾（一个说 100 万，一个说 500 万），它最优雅的恢复和汇报策略是什么？

## 第 7 天｜Agent Engineering Boss：设计并测试受控 Agent

**学习目标**：整合目标、任务、工具、循环、状态、记忆、权限、评测与恢复机制。

**Boss 实验**：以调研助理为统一案例，提交 Agent 规格、工具 Schema、状态图、权限表、记忆策略、停止条件、测试日志和失败复盘。

**达标标准**：Agent 能在边界内完成任务；关键动作可审计；失败可恢复；不能完成时能安全停止并解释原因。

**代表性拟题**
1. [架构] 画出用户、模型、Agent 控制器、工具、状态库与知识库之间的数据流。
2. [红队测试] 设计资料注入、工具超时、重复执行、权限越界和证据不足五类测试。
3. [日志诊断] 给出一次失败运行，定位问题属于 Plan、Tool、State、Memory 还是 Permission。
4. [权衡] 提高 Agent 自主性会怎样影响效率、可预测性和风险？
5. [Boss 开放题] 提交完整 Agent 设计与两次测试记录，其中一次必须失败，并说明修复与回归结果。
