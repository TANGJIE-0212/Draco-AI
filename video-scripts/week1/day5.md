## 核心概念

### AI 有两种记忆

AI 的记忆分两种，必须把它们分清楚，否则会产生很多困惑。

第一种是**长期记忆（权重）**：训练时学到的所有知识，就像你背过的所有书、积累的所有经验，已经固化进了模型的神经网络参数里。这部分只读不写，对话结束后不会因为你说了什么而改变。

第二种是**短期记忆（Context，上下文）**：当前对话里的内容，就像考试时的草稿纸。写在上面的东西，一关闭对话、一刷新页面就全消失了。下次开新对话，草稿纸清空重来。

### Context Window 是什么？

Context Window（上下文窗口）就是这张草稿纸的大小。模型每次能"看到"和"记住"的信息量是有上限的，不能无限大。

为什么不能无限大？因为 Transformer 的 Attention 计算复杂度是平方级增长的。上下文长度翻倍，计算量和显存消耗就变成 4 倍。所以越大的 Context Window，对算力要求越高，成本越贵。

### 滑动窗口：旧的不去，新的不来

当对话内容超过了 Context Window 的上限，最早输入的内容会被强制丢弃，新内容才能进来，这叫滑动窗口（Sliding Window）。

这就解释了一个常见现象：你和 AI 聊了很久，它突然忘了你最开始设定的名字或角色。不是 AI 出故障了，是最开始的内容已经被挤出了窗口范围。

### 迷失在中间

即便窗口足够大（比如 128k Token），AI 也不一定能均匀地记住所有内容。研究发现，AI 对开头和结尾的信息记得最牢，中间的内容反而容易被忽略。这个现象叫"Lost in the Middle（迷失在中间）"。

实际影响：如果你给 AI 一份很长的文档，最重要的指令最好放在开头或结尾，放在中间容易被忽视。

### Input 和 Output 共享窗口额度

还有一个重要细节经常被忽略：输入（你发给 AI 的内容）和输出（AI 写出来的内容）共享同一个 Context Window 的额度。

如果你把一篇占满 90% 窗口的长文档塞给 AI，让它"详细扩写"，AI 只剩 10% 的空间来写扩写内容，写到一半就会截断。这不是 AI 能力不足，是数学上就写不完。

### RAG：带书进考场

既然 Context Window 有限而且昂贵，有没有更聪明的方法？

RAG（Retrieval-Augmented Generation，检索增强生成）的思路很简单，用一个比喻来说：**允许学生带书进考场**。

具体流程分四步：
1. **建立知识库**：把所有资料（公司文档、法律条文、产品手册）提前存进向量数据库，每段内容都变成向量坐标
2. **用户提问**：把问题也变成向量
3. **相似度检索**：在向量数据库里找出距离最近、最相关的几段内容（就像考试时翻书找到那几页）
4. **拼入 Prompt**：把检索到的内容和用户问题一起发给 AI，AI 基于这些材料生成答案

这样 AI 就不需要把整本书都背下来，每次只把最相关的几页放进 Context Window，既节省算力又提高了准确性。

### 什么时候必须用 RAG？

有些知识模型本身就有，不需要 RAG：
- 问 2008 年北京奥运会是什么时候 → 模型自带知识
- 翻译一段英文 → 模型自带能力

但有些情况必须 RAG：
- 询问今天公司内部的最新库存数据 → 私有且实时变化的信息，模型根本没见过
- 查询特定合同条款 → 私密文件，没有训练进模型
- 任何"知识截止日期"之后的新事件

### RAG 能减少幻觉

RAG 还有一个额外的好处：有了真实资料作为依据，AI 编造内容的空间就被大幅压缩了。让它基于材料回答，而不是凭空想象，幻觉率会显著下降。

### 超大 Context Window 出来了，RAG 还有用吗？

有人问：Gemini 已经支持 100 万 Token 的超大窗口，RAG 还需要吗？

答案是仍然需要，原因有三：
- **成本**：每次把整本书塞进 Context 比检索几段资料贵得多
- **速度**：大 Context 处理慢，RAG 只检索相关片段更快
- **权限控制**：不同用户应该看到不同内容，RAG 可以做精确的访问控制

## 常见误区

**误区一：我在对话里说的内容会让 AI 变聪明。**
不对。对话内容只存在于当前的 Context Window 里，不会更新模型的训练权重。关闭对话后，AI 不记得你说过什么。

**误区二：窗口越大越好，没有缺点。**
不对。大窗口计算量大、成本高、速度慢，还有"迷失在中间"的问题。要根据场景选择合适的策略。

**误区三：RAG 一定能准确回答。**
不对。如果检索步骤出了问题，返回了不相关的文档片段，AI 就会基于错误材料作答。RAG 的质量上限取决于检索的质量。
