## 核心概念

### 两类模型：围墙花园 vs 荒野求生

今天先把 AI 模型世界里的两个阵营说清楚。

**闭源模型（Closed Source）**：GPT-4、Claude、Gemini 这类。你通过 API 访问，按 Token 付费。优点是性能强、维护简单、稳定可靠；缺点是贵、数据会经过供应商的服务器（有隐私风险）、你看不到模型内部是怎么工作的。

**开源模型（Open Source）**：Llama 3、Mistral、Qwen 这类。你下载模型权重文件，跑在自己的服务器或电脑上。优点是私有、可以定制改造、没有按量付费的 API 费用；缺点是部署麻烦、需要自己维护、对硬件要求高。

### 开源不等于完全免费

这是一个常见误区。开源模型的软件本身是免费的，但你需要支付 GPU 的运行费用（电费或云算力租用费）。跑一个 70B 参数的大模型，显卡要求很高，长期运行的成本可能远超直接调 API。

### 参数量：模型的"体型"

模型名字后面的 7B、13B、70B 代表参数数量（B = Billion，十亿）。

**大模型（70B 以上）**：推理能力强、逻辑好，但需要大量显存，推理速度慢，价格贵。

**小模型（7B/8B）**：反应快，可以在普通显卡甚至手机上运行，适合分类、摘要、格式转换等任务，但复杂推理能力弱。

原则：**用刚好够用的模型，不用杀鸡用牛刀。** 从文本中提取人名，8B 的模型完全够用，不需要 GPT-4。

### 量化：把大象塞进小笼子

想在 24GB 显存的显卡上跑一个通常需要 140GB 显存的 70B 模型？有一个方法：量化（Quantization）。

量化就像把高清图片压缩成 JPG——把模型参数从 16-bit 压缩成 4-bit，精度略有损失，但显存需求大幅下降，有时能压缩到原来的四分之一。这让在消费级硬件上跑大模型成为可能。

### 为不同客户选择不同方案

| 需求 | 推荐方案 |
|------|---------|
| 数据绝对不能出内网（银行/政府）| 本地部署开源模型 |
| 独立开发者，快速验证想法，没有显卡 | 云端 API 按量付费 |
| 需要研究模型底层架构的研究员 | 下载开源模型权重 |
| 企业客服，需要高稳定性，不想招运维 | 有 SLA 保障的企业级闭源 API |

### 第一周技术栈完整回顾

这一周学的不是零散的知识点，而是一个完整的分层技术栈。我们从最底层开始往上走：

**第一层（原理层）**：AI 的本质是 Next Token Prediction，逐词预测，统计规律。Token 是最小处理单位，Embedding 把 Token 变成语义坐标。

**第二层（引擎层）**：Transformer 架构，通过 Self-Attention 并行处理整个序列，让每个词都能感知上下文。FFN 负责知识存储和推理。

**第三层（记忆层）**：Context Window 是短期工作台，有大小限制。RAG 通过向量数据库扩展了可访问的知识范围。

**第四层（控制层）**：Temperature、Top-K、Top-P 控制输出的随机程度，对应不同任务类型要调不同参数。

**第五层（应用层）**：Prompt 是和 AI 沟通的语言，Agent 是能自主使用工具完成任务的 AI。这是下面几周的主题。

### 第一周最重要的底层直觉

把这些概念融合在一起，最重要的一句话是：**AI 是一个数学极好的接龙游戏玩家，它猜词的能力和我们对它的所有误解，都从这里长出来。**

它不理解你，它在算概率。它不记得你，除非你在 Context Window 里。它不知道真相，除非你把资料喂给它。

知道了这些，你就知道怎么用它，也知道它的边界在哪里。

## AI 技术栈对应关系

| 层次 | 技术 | 类比 |
|------|------|------|
| 算力层 | GPU / TPU | 发动机 |
| 模型层 | Transformer / 权重 | 大脑本体 |
| 记忆层 | Vector DB / Context | 草稿纸 + 图书馆 |
| 控制层 | Temperature / Top-P | 情绪旋钮 |
| 应用层 | Prompt / Agent | 语言和助手 |

## 常见误区汇总（第一周）

**开源 = 免费** → 软件免费，算力不免费

**大模型更好** → 大模型更聪明但更贵，小任务用小模型

**Context 越大越省心** → 大 Context 贵且有"迷失在中间"问题

**RAG 和大 Context 二选一** → 两者各有优势，很多场景同时使用

**幻觉靠调温度解决** → 治幻觉靠提供真实资料（RAG），不是调参数
