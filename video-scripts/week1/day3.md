## 核心概念

### AI 不认识字，它只认数字

AI 在处理文字之前，会先用一把虚拟的剪刀把文本切碎。这把剪刀叫 Tokenizer，切出来的碎片叫 Token。

关键点是：Token 不等于单词，也不等于汉字。常见的词可能是一个 Token，生僻词或复杂组合会被切成多个碎片。如果 AI 是一个乐高玩家，Token 就是那些最小的积木块，不是搭好的城堡，也不是说明书。

### Token 引发的经典 Bug

你可能见过 AI 数不清"Strawberry"里有几个字母"r"。背后的原因正是 Token 切分。

在 AI 眼里，"Strawberry"被切成了"Straw"和"berry"两个整数 ID。它根本看不到单词内部的字母，就像你只看到两块乐高砖头，看不到砖头内部的颗粒数量。

同理，数字"9.11"可能被切成三个 Token："9"、"."、"11"。于是比较 9.11 和 9.8 的大小时，AI 会觉得 11 比 8 大——因为 Tokenizer 破坏了数字的整体数值意义。

### Token 是计费单位

Token 也是 AI API 的计费单位。粗略换算：
- 英文：1000 个单词 ≈ 1300 个 Token
- 中文：1 个汉字 ≈ 1~2 个 Token

这也是为什么中文调用 API 有时消耗更快——中文字符的 Token 密度和英文不同。

### Token 变成数字之后，怎么赋予意义？

切好的 Token 只是一串死板的数字 ID，就像图书馆里每本书的编号。这些编号能告诉你书在哪个书架，但说不清楚这本书讲什么、和哪本书主题相近。

这时候就需要 Embedding（嵌入）。Embedding 做的事是：把每个 Token 扔进一个几千维的"语义宇宙"里，给它一个坐标。

这个宇宙有一个核心规律：**意思越相近，坐标越近。**

"猫"和"狗"在这个空间里是近邻。"猫"和"汽车"就离得很远。没有 Embedding，"猫"和"狗"的距离在数学上和"猫"和"汽车"完全一样——因为它们都只是两个毫不相关的数字 ID。

### 向量之间怎么计算距离？

AI 判断两个词意思是否相近，是计算它们向量之间的夹角。夹角越小（方向越一致），意思越相似；夹角 90 度，毫无关系；夹角 180 度，意思相反。这种方法叫余弦相似度。

### 向量还能做算术？

Embedding 最神奇的地方是它支持语义代数。因为词语被编码成了向量，可以直接做加减法。

经典例子：**国王 - 男人 + 女人 ≈ 女王**

这说明在 Embedding 空间里，"性别"这个维度是有方向的，可以被单独操作。同理，巴黎 - 法国 + 日本 ≈ 东京。

### 一词多义怎么办？

"苹果"可以是水果，也可以是科技公司。"银行"可以是金融机构，也可以是河岸。

现代 Transformer 架构里，Embedding 是动态的，会根据上下文变化。同一个词，在不同句子里会落在语义宇宙的不同位置。"I went to the bank to deposit money"里的 bank，它的坐标会向"金融""货币"靠拢；而"The boat is near the bank of the river"里的 bank，坐标就偏向"河流""自然"。

### Embedding 和 RAG 的关系

当你问 AI"怎么做番茄炒蛋"，AI 会把这个问题变成一个向量，然后去数据库里找距离最近的文档向量。这就是 RAG（检索增强生成）的核心——用向量搜索找最相关的资料。Embedding 是整个知识库检索能力的基础。

## 从文字到理解的四步流水线

| 步骤 | 名称 | 在做什么 |
|------|------|---------|
| 1 | 输入文本 | 原始人类语言，还没被处理 |
| 2 | Tokenization | 把文字切成整数 ID 序列 |
| 3 | Embedding | 把 ID 映射到高维空间坐标，赋予语义距离 |
| 4 | Attention | 让每个 Token 吸收上下文信息，坐标变得带语境 |

## 常见误区

**误区一：AI 是在"阅读"文字。**
不对。AI 接触到的是数字，不是文字。Tokenizer 把文字变成数字之后，AI 才能处理。

**误区二：Embedding 是固定的。**
现代模型的 Embedding 是动态的（Contextual Embedding），同一个词在不同上下文里坐标不同。

**误区三：Token 越多表示 AI 越聪明。**
Token 是计量单位，不是智力指标。一个问题消耗 500 Token，不代表比消耗 50 Token 的回答更好。
