# Draco AI V3：用户画像、购买理由、课程大纲与上架形态

> 状态：讨论稿 v0.1  
> 核心假设：家长是 Buyer，12–15 岁青少年是 User  
> 依据：Draco-AI GitHub 现有 V1/V2 课程材料、官方监管文件与微信开放文档

## 1. 产品定位

### 一句话定位

**一套面向 12–15 岁零基础青少年的 AI 创造力课程：四周完成第一个 AI 作品，同时学会提问、验证、安全使用和与 Agent 协作。**

### 不是

- 不是以背诵 Token、Transformer、RAG 等术语为目标的 AI 理论课。
- 不是教孩子用 AI 直接完成作业的“提分工具”。
- 不是开放式、无限制的儿童聊天机器人。
- 不是少儿编程课的简单换皮。

### 核心价值

- **对孩子**：从“玩过 AI”变成“能用 AI 做出作品，并知道它为什么会错”。
- **对家长**：孩子获得 AI 时代的判断力、创造力和安全意识，而不是形成依赖。
- **最终证明**：每个孩子完成一个可展示、可讲解、可复盘的 AI 项目。

## 2. 核心用户画像

### Primary User：探索型初中生

| 项目 | 定义 |
|---|---|
| 年龄 | 12–15 岁，以初一至初三为首发范围 |
| AI 经验 | 用过豆包、Kimi、ChatGPT 或生图工具，但主要停留在问答案、玩图片 |
| 技术基础 | 不要求编程；能独立使用电脑、浏览器和常见文档工具 |
| 兴趣 | 科技、游戏、动漫、视频、科普、创作，至少命中一项 |
| 核心诉求 | 想做出“酷而且能展示”的东西；不想听长期理论课 |
| 主要障碍 | 不知道从哪里开始；容易复制 Prompt；不会验证答案；工具切换成本高 |
| 使用环境 | 周末或放学后，优先使用家庭电脑；家长可在旁辅助但不必陪学全程 |

**核心 Job to be Done：**

> 当我对 AI 感兴趣但不知道能拿它做什么时，我希望通过短任务做出一个自己的作品，这样我不仅觉得 AI 很酷，也能向父母和同学解释我是怎么做出来的。

### Primary Buyer：理性投入型家长

| 项目 | 定义 |
|---|---|
| 典型阶段 | 孩子处于初中阶段，家长关注未来能力但不希望增加应试负担 |
| 核心焦虑 | 孩子落后于 AI 时代；把 AI 当抄作业工具；接触不安全内容；课程只讲概念没有成果 |
| 购买标准 | 课程安全、体系清楚、时间可控、有作品成果、不过度娱乐化、无需家长全程陪伴 |
| 主要反对理由 | “网上免费教程很多”“AI 变化太快”“孩子学完会不会更依赖 AI”“是不是换皮编程课” |
| 信任证据 | 试看任务、课程大纲、隐私说明、家长学习报告、真实作品样例、明确的能力评价标准 |

**核心 Job to be Done：**

> 当我担心孩子只会消费 AI 生成结果时，我希望有一套安全、短周期、有成果的课程，让孩子学会正确使用和判断 AI，而不是增加一门需要我监督的补习课。

### 非目标用户

- 需要竞赛算法、模型训练或 Python 深度学习课程的高阶学生。
- 主要目标是用 AI 代写作业或直接获得标准答案的用户。
- 10 岁以下且不能独立阅读和操作电脑的儿童。
- 仅希望获得职业提效工具的成年人。

## 3. 家长购买理由

### 核心购买主张

> **不是让孩子更早依赖 AI，而是让孩子更早学会驾驭、质疑和安全使用 AI。**

| 购买理由 | 家长价值 | 产品证据 |
|---|---|---|
| 有明确成果 | 不是“学过”，而是四周完成一个可展示作品 | 毕业项目、作品说明书、过程记录 |
| 培养判断力 | 孩子知道 AI 会编造，能检查来源与事实 | “AI 侦探”任务、引用核验、翻车复盘 |
| 培养创造力 | 从提出问题到设计、制作和改进作品 | 每周作品累积、开放式选题 |
| 安全可控 | 不以开放聊天和社交留住孩子 | 内容边界、默认私密、家长控制、时间提示 |
| 时间成本可控 | 不与学校学习形成长期冲突 | 短课时、四周项目制、可暂停继续 |
| 不要求编程 | 降低第一步门槛，同时保留进阶空间 | 可视化工具和自然语言交互为主 |
| 家长看得懂成长 | 不只展示答题正确率 | 能力雷达、作品里程碑、风险意识反馈 |

### 推荐销售话术

**主标题：** 四周，让孩子完成第一个真正属于自己的 AI 作品。

**副标题：** 不背术语、不教抄答案；学会提出好问题、验证 AI、保护隐私，并让 Agent 帮自己完成一个项目。

**三条信任信息：**

1. 每周一个作品，不以观看时长衡量学习。
2. 默认保护隐私，不鼓励上传真实姓名、学校、照片和作业成绩。
3. 家长能看到能力成长，但默认看不到孩子的私人创作内容。

### 需要验证的关键假设

- [Requires Confirmation] 家长最愿意为“AI 素养”“创造力作品”还是“未来竞争力”付费？
- [Requires Confirmation] 四周周期与单次学习时长是否符合目标家庭节奏？
- [Requires Confirmation] 家长是否接受孩子使用第三方 AI 工具，还是更偏好课程内封闭体验？
- [Requires Confirmation] 首发采用一次性买课、训练营还是会员制？

## 4. 四周课程大纲

### 课程设计原则

- **作品驱动**：每周完成一个作品组件，第四周合成毕业作品。
- **先体验后解释**：先让学生看到现象，再引出必要原理。
- **少工具切换**：主线最多使用一个内置 AI 环境和一至两个外部工具。
- **验证优先**：每次生成都包含检查、比较或修改动作。
- **隐私嵌入式教学**：安全不是最后一课，而是每个任务的执行条件。
- **单次短闭环**：每课建议由故事、实验、反思和作品进度组成；具体时长需用户测试确定。

### Week 1：识破 AI 的魔法

**学习目标：** 建立正确心智模型，理解 AI 能做什么、为什么会犯错，以及如何验证。

| Day | 核心任务 | 作品积累 |
|---|---|---|
| 1 | 同一个问题问人和 AI，观察差异 | 我的 AI 能力地图 |
| 2 | 用“文字接龙”实验理解生成原理 | AI 工作原理卡片 |
| 3 | 制造一次 AI 幻觉并找出证据 | 翻车案例记录 |
| 4 | 比较三个来源，判断哪条信息可信 | 信息核验清单 |
| 5 | 识别偏见、过度自信和伪引用 | AI 风险警示卡 |
| 6 | 隐私实验：什么信息不能交给 AI | 我的 AI 隐私边界 |
| 7 | Boss：制作《AI 真相侦探报告》 | Week 1 作品 |

### Week 2：教会 AI 理解我

**学习目标：** 不背 Prompt 公式，通过对比实验掌握目标、背景、示例、约束和迭代。

| Day | 核心任务 | 作品积累 |
|---|---|---|
| 1 | 比较模糊要求与清晰目标 | 好问题改写器 |
| 2 | 给 AI 补充必要背景，但不泄露隐私 | 安全上下文卡 |
| 3 | 用示例教 AI 模仿风格 | 示例素材库 |
| 4 | 规定结构、长度和禁止事项 | 输出控制卡 |
| 5 | 不满意时定位问题并迭代 | 三轮改进记录 |
| 6 | 区分 AI 建议与应由人决定的事项 | 人机责任边界 |
| 7 | Boss：设计一个个性化学习伙伴 | Week 2 作品 |

### Week 3：AI 多模态内容创作

**学习目标：** 把可靠的公开资料依次转化为脚本、主视觉、连续镜头、配音与字幕，最终完成一支 15—30 秒知识故事短片，同时理解事实核验、版权、隐私和 AI 生成标注责任。

| Day | 核心任务 | 作品积累 |
|---|---|---|
| 1 | 从公开资料提取一个可靠事实并写成短脚本 | 脚本来源卡 + 旁白初稿 |
| 2 | 理解参考图片，区分观察、解释和不确定性 | 图片观察卡 |
| 3 | 用五段式提示词生成知识主视觉 | 主视觉 + 验收记录 |
| 4 | 用视觉锚点迭代并保持跨镜头一致 | 连续镜头图 + 版本记录 |
| 5 | 将静态图片转成 2—3 个视频镜头 | 视频草稿 + 镜头运动表 |
| 6 | 加入配音、字幕和音乐并完成发布检查 | 15—30 秒粗剪 + 检查表 |
| 7 | Boss：导出并交付 15—30 秒知识故事短片 | 成片 + 完整交付记录 |

### Week 4：召唤自己的 Agent

**学习目标：** 理解目标、步骤、工具、记忆、检查和停止条件，完成一个受控的多步 Agent 项目。

| Day | 核心任务 | 作品积累 |
|---|---|---|
| 1 | 对比 Chatbot 与 Agent | 任务选型卡 |
| 2 | 观察 Agent 如何拆解一个研究任务 | 任务分解图 |
| 3 | 为 Agent 选择工具和资料 | 工具与资料清单 |
| 4 | 故意让 Agent 跑偏，再设置检查点 | 失败与恢复规则 |
| 5 | 设计有限、可删除的“记忆” | 记忆边界卡 |
| 6 | 搭建并试跑自己的 Agent | 毕业作品测试版 |
| 7 | Boss：展示、解释和复盘毕业作品 | 成品 +《我的 AI 员工说明书》 |

### 毕业作品范围

学生从以下方向中选择一个，避免完全开放命题：

- 科普研究助手：围绕一个兴趣主题收集、比较和引用资料。
- 阅读伙伴：帮助理解公开文章或允许使用的学习材料，但不直接代写作业。
- 创作助手：完成角色设定、故事结构、视觉草图和迭代。
- 兴趣计划助手：为阅读、运动、观星或手工项目制定并跟踪计划。

**毕业评估维度：** 问题定义、任务拆解、证据验证、创意表达、隐私安全、人机分工、复盘能力。具体分数权重在试课后确定。

## 5. 上架形态建议

### 结论

**建议采用“响应式 Web/PWA 做产品本体 + 微信小程序做家长购买与回流入口”的双端策略；首发不做原生 App。**

关键原因是：

- 学生需要上传资料、比较来源、制作作品，**电脑网页比手机更适合深度学习和创作**。
- 家长的发现、分享、购买和查看学习报告，**微信小程序摩擦更低**。
- 原生 App 会同时增加 iOS/Android 开发、商店审核、支付和版本维护成本，却不能自动消除未成年人或生成式 AI 的合规义务。
- 当前 GitHub 产品本身已经是 React Web，先做 Web 能最大化复用并最快验证课程价值。

### 三种形态比较

| 维度 | Web/PWA | 微信小程序 | 原生 App |
|---|---|---|---|
| MVP 速度 | 最快，可复用现有 React | 中等，需要适配微信能力 | 最慢，双端与商店流程 |
| 学生创作体验 | 最佳，适合电脑与键盘 | 手机方便，复杂创作偏弱 | 手机体验好，但不一定适合长任务 |
| 家长获客/分享 | 需要链接传播 | 最佳，微信内闭环 | 下载摩擦最大 |
| 支付 | 可自建，但需完整交易合规 | 方便但受虚拟支付规则约束 | 受应用商店内购规则约束 |
| 迭代速度 | 最快 | 需平台审核 | 需商店审核 |
| 平台依赖 | 较低 | 高度依赖微信规则 | 依赖 Apple/Android 商店规则 |
| 合规复杂度 | 中等 | 中高 | 高 |
| 当前阶段建议 | **产品本体/P0** | **家长入口/P1** | 暂缓 |

### 推荐用户链路

1. 家长在微信内容、社群或朋友分享中看到课程。
2. 进入小程序查看课程说明、作品样例、隐私承诺和试看任务。
3. 家长完成授权与购买，创建家庭学习码。
4. 孩子在电脑浏览器输入学习码，进入响应式 Web 学习。
5. 学习成果默认私密保存；孩子决定哪些作品提交给家长查看。
6. 家长在小程序查看里程碑、能力反馈和下一周说明。

这种设计将 **Buyer Journey 放在微信**，将 **Learning Journey 放在 Web**，比强迫两类用户共用一个移动端更合理。

### 为什么暂不做原生 App

- 产品尚未验证付费意愿和完课率，不值得提前承担双端成本。
- App Store/安卓商店并非唯一合规风险来源；未成年人、个人信息、内容安全和生成式 AI 义务与服务本身相关。
- 课程对电脑操作有天然需求，手机 App 可能反而降低作品质量。
- 当出现稳定复访、离线需求、系统级创作能力或明确商店获客价值后，再评估 App。

## 6. 合规与 Privacy by Design 初判

> 以下是产品规划判断，不构成法律意见。正式上线前需要中国法律顾问、平台运营方和 Tech Lead 联合确认具体资质、备案、模型接入和数据流。

### 与形态无关、必须先解决的事项

- **未成年人保护**：在线教育服务应按年龄和认知能力提供内容；需要防沉迷、投诉举报、内容安全和监护支持设计。
- **儿童信息**：不满 14 周岁用户的个人信息属于高保护范围；如处理，应取得监护人同意并制定专门规则。
- **最小必要**：不得将非必要个人信息授权作为基本课程使用前提。
- **用户权利**：需要提供查询、复制、更正、删除和撤回同意的明确入口。
- **内容治理**：开放式 AI 输入输出需要安全策略、拦截与人工处置流程；面向未成年人时要求更高。
- **生成式 AI 服务**：如果 Draco 直接向公众提供生成内容，而不是仅链接到第三方已合规工具，需要专项评估适用义务、模型/算法备案、安全评估及内容标识等问题。
- **数据跨境**：若调用境外模型或将未成年人输入、作品、日志发送到境外，需先由法务与 Tech Lead 评估；MVP 建议避免未成年人个人数据跨境。

### 平台特有事项

| 平台 | 需重点确认 |
|---|---|
| Web/PWA | 域名与 ICP 备案、网络安全、支付与消费者权益、隐私政策、生成内容责任 |
| 微信小程序 | 小程序备案、主体认证、服务类目与教育资质、内容审核、用户隐私保护指引、虚拟支付规则 |
| 原生 App | APP 备案、应用商店审核、隐私清单/SDK 治理、儿童或未成年人分类、应用内购买规则、版本审核 |

### 小程序支付提醒

微信官方文档将课程解锁、订阅内容等视为虚拟商品范畴，购买通常需要接入小程序虚拟支付。官方当前文档显示：

- 主体需为已认证的企业、事业单位或个体工商户，并完成相关资料与商户配置。
- iOS 端有独立支付与退款流程，支付会路由到 Apple 支付。
- iOS 端标准费率和具体优惠可能变化，不能在商业模型中假设长期固定费率。

因此，**不要先假设“小程序一定比网页付费简单或便宜”**；应在确定主体、商品形态和服务类目后向微信平台确认。

### MVP 隐私架构建议

- 由家长创建主账户，孩子使用昵称和家庭学习码，不要求手机号、真实姓名、学校或身份证信息。
- 年龄只收集年龄段，而非精确生日，除非合规流程要求。
- 作品默认私密，不提供公开社区、陌生人评论或私信。
- 对上传区域提供实时提醒与检测：不上传人脸、学生证、学校名称、住址和他人信息。
- 输入与作品不用于模型训练，除非未来另行获得清晰、单独且可撤回的有效同意。
- 第三方模型仅接收完成任务所必需的最小内容；建立供应商和数据流清单。
- 设置保留期限，到期自动删除，并让家长和孩子可主动删除。
- 家长看到学习进度与能力反馈；私人创作内容默认不向家长逐字开放，兼顾监护和青少年隐私。

## 7. 建议的 MVP 范围

### P0

- Web 端 Week 1 完整课程与 Week 4 Agent 概念试玩。
- 家长落地页、课程说明、作品样例和隐私承诺。
- 无实名学习码、进度保存、作品私密保存与删除。
- 内置受控任务，不提供完全开放的无限聊天。
- 一份家长学习反馈样例。

### P1

- 微信小程序家长入口、购买、家庭绑定与里程碑通知。
- 完整四周课程。
- 家长报告与孩子选择性作品分享。
- 供应商级内容安全与敏感信息检测。

### 暂不做

- 原生 App。
- 公共作品社区、排行榜和陌生人互动。
- 无限制 AI 陪聊。
- 自动代写学校作业。
- 未经专项评估的境外模型数据传输。

## 8. 决策与验证计划

### 当前建议决策

- **Target**：12–15 岁零基础、对科技或创作感兴趣的青少年。
- **Buyer**：关注未来能力、安全和作品结果的家长。
- **课程**：四周作品驱动，以 V2 教学方法重构 V1 核心知识。
- **终端**：Web/PWA 产品本体，小程序承接家长链路，原生 App 暂缓。

### 上线前必须回答

1. 家长愿意为什么价值付费？
2. 孩子是否能独立完成首个任务并主动继续？
3. 学生完成作品是否必须调用开放式生成模型？
4. 第三方模型、存储和分析 SDK 的数据分别流向哪里？
5. 主体是否具备对应小程序类目、支付和在线教育所需条件？
6. 免费试看与付费课程的边界如何设计？

### 首轮概念测试
